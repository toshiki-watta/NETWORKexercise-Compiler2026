# コンパイラ開発：トップダウン実装ロードマップ

指導書およびスタートアップガイドに基づき、まずはモジュール設計（ファイル分割）を確定させ、その後構文規則の上位（プログラム全体）から下位（式・因子）へとトップダウンで実装を展開する。

## 📅 フェーズ 1: 設計とファイル分割（リファクタリング）
まずは現在の `parse.c` に混在している機能を切り離し、見通しを良くする。

- [ ] **共通ヘッダの作成 (`common.h` / `compiler.h`)**
  - [ ] トークン情報（`extern TOKEN tok;`）や共通マクロ、エラー関数の宣言を集約
- [ ] **シンボルテーブルの分離 (`table.c`, `table.h`)**
  - [ ] `s_table` 配列、`sym_lookup()`、`sym_install()` を移動
- [ ] **コード生成・ラベル管理の分離 (`codegen.c`, `codegen.h`)**
  - [ ] `new_label()`、`emit_label()`、およびアセンブリ出力補助関数を移動
- [ ] **構文解析の骨格化 (`parse.c`)**
  - [ ] `parse.c` には純粋な構文解析ルーチン（`compiler`, `outblock`, `statement`）のみを残す
- [ ] **`Makefile` の更新**
  - [ ] 分割したオブジェクトファイル (`main.o`, `parse.o`, `table.o`, `codegen.o`) の依存関係を記述

## 📅 フェーズ 2: 構文解析のトップダウン再構築
指導書の構文規則（BNF）に忠実な関数群を定義し、上から順に組む。

- [ ] **プログラム全体の解析 (`compiler`)**
  - [ ] 末尾のピリオド `.` のチェックを正しく行う（現在コメントアウトされている部分の修正）
- [ ] **変数宣言ブロックの解析 (`outblock`)**
  - [ ] 複数の `VAR` 宣言文が並んだ場合でも、型やカンマ、セミコロンを正しくパースする
- [ ] **文の解析 (`statement`)**
  - [ ] `if` 文：`else` 節を伴う構文規則を厳密にパースし、正しいラベル分岐を出力する
  - [ ] `while` 文：ループ条件とジャンプ命令の整合性を確保する
  - [ ] `begin-end` 文：再帰的に複数の `statement` を処理できるようにする

## 📅 フェーズ 3: 式の評価階層の実装（最重要）
現在の `eval_to_r0` を廃止し、指導書の規則通りに演算子の優先順位を反映したトップダウン解析関数を実装する。

- [ ] **`expression()` の実装（式：`+`, `-` の処理）**
  - [ ] 単一の `term` または `term` 同士の加減算を処理する
- [ ] **`term()` の実装（項：`*`, `/`, `DIV` の処理）**
  - [ ] 単一の `factor` または `factor` 同士の乗除算を処理する
- [ ] **`factor()` の実装（因子：変数・数値・カッコの処理）**
  - [ ] 識別子（変数）、数値定数を処理する
  - [ ] （発展）カッコ `( expression )` が来たら `expression()` を再帰呼び出しする構造にする

## 📅 フェーズ 4: テストと検証
- [ ] `samples/` にある正常系プログラムが正しくアセンブリ（`a.asm`）に変換されるか確認
- [ ] `samples/failure/` にある異常系プログラムを突っ込んだとき、自作の `error()` が適切に動作してコンパイルエラーを吐くか検証
