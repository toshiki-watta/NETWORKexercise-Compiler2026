## 🛠️ 作成実験 4：実装手順（ロードマップ）

大きな流れとして、**「①データ構造の拡張（記号表）」→「②手続き定義のパースとフレーム生成」→「③手続き呼び出しのパースと引数処理」→「④変数アクセスの局所化（BR相対）」** という4つのステップで進めます。

---

### ステップ 1：データ構造（記号表）の拡張

まずは手続き名や局所変数を管理できるように、記号表を2階層に拡張します。

* **大域記号表と局所記号表の分離**
* プログラム全体で使える「大域変数」や「手続き名」を登録する `GlobalTable` と、現在パース中の手続き内だけで有効な「引数」や「局所変数」を登録する `LocalTable` を用意します。


* **探索ロジックの変更**
* 変数名（`ident`）を見つけたときの検索順序を、**「まず `LocalTable` を探し、見つからなければ `GlobalTable` を探す」** という2段階（シャドーイング対応）に変更します。


* **アドレス管理の変更**
* **大域変数**：固定アドレス（スタックの底からの絶対番地）
* **局所変数・引数**：ベースレジスタ（`BR`）からの**相対アドレス（オフセット）**



---

### ステップ 2：手続き定義（`procedure`）のパースとコード生成

ハノイの塔の例にある `procedure hanoi(a, b, c, n); var i; ...` を処理する部分を作ります。

```text
【スタックフレームの構造（イメージ）】
高位アドレス (スタックの底方向)
   +-------------------+
   | 引数 (n, c, b, a) |  <- 呼び出し側が事前に push
   +-------------------+
   | 戻り番地 (PC)     |  <- call 命令で自動 push
   +-------------------+
   | 動的リンク (旧BR) |  <- 手続きの先頭で push
   +-------------------+ <--- 現在のベースレジスタ (BR)
   | 局所変数 (i)      |  <- 手続きの先頭で SP を進めて確保
   +-------------------+
低位アドレス (SPが指す先)

```

* **プロローグ（手続きの入り口）の自動生成**
手続きの構文に入ったら、その手続きの開始ラベルを出力し、続いて以下のスタックフレーム構築アセンブリ（プロローグ）を出力します。
1. 現在のベースレジスタの値を退避： `push BR`（これが動的リンクになります）
2. BRを現在のスタックトップに更新： `mov BR, SP`
3. 局所変数領域の確保： `sub SP, [局所変数の個数]` （SPを進める）


* **エピローグ（手続きの出口）の自動生成**
手続きのパースの終わり（`end;`）に達したら、フレームを解体して戻るアセンブリ（エピローグ）を出力します。
1. 局所変数領域の解放： `mov SP, BR` （SPをBRの位置に戻す）
2. 元のBRの値を復元： `pop BR`
3. 呼び出し元へ復帰： `ret`



---

### ステップ 3：手続き呼び出し（`call` / 代入文との衝突回避）の変更

前回の補足資料にもあった、「LL(1)文法ではない問題」を解決しつつ、呼び出しコードを作ります。

* **文（`statement`）の先頭が `ident` だった場合の分岐**
* 記号表を検索し、その識別子が `PROC`（手続き）であれば手続き呼び出し、`VAR`（変数）なら代入文、として分岐させます。


* **引数（値渡し）のパースと `push**`
* `hanoi(1, 2, 3, n)` のカッコ内をパースします。
* 引数の数式 `expression()` を評価するたびに、結果が入ったレジスタを `push` してスタックに積んでいきます。


* **`call` 命令の発行**
* すべての引数を積み終わったら、大域記号表から引っ張ってきた手続きの開始ラベルに対して `call [ラベル]` 命令を出力します。
* ※手続きから戻ってきた後、積んだ引数の分だけスタックポインタを戻す（`add SP, [引数の数]`）後処理も忘れないようにします。



---

### ステップ 4：変数アクセス命令の「ベースレジスタ（BR）相対」化

手続きの再帰呼び出しに対応するため、変数へのアクセス方法を動的なアドレス（BRからの相対位置）に切り替えます。

* **大域変数へのアクセス**
* スタックの最下層（0番地など）に固定されているため、これまで通りの絶対アドレス（または大域用のベース）でアクセスします。


* **局所変数・引数へのアクセス**
* コンパイル時に確定した「BRからのオフセット」を使って、アセンブリを生成します。
* 例：`mov r0, [BR + オフセット]`
* ※引数はBRより高い番地（プラス側）、局所変数はBRより低い番地（マイナス側）に配置されるため、符号の計算に注意してください。

## 💡 forward文（前方参照）への簡単なアプローチ

資料の最後にあった `forward`（相互再帰などで、定義より前に呼び出しが出るケース）の対応ですが、資料に「宣言されていない手続きが呼び出されていることを発見した段階で、開始アドレスを仮定してもよい」とあります。

一番簡単な実装は、「手続き名が出てきたら、未定義であってもとりあえず記号表に登録し、ラベル名（例: `L_proc_hanoi`）だけを確定させて `call` 命令を出力しておく」方法です。
アセンブリのラベル（文字列）として出力しておけば、最終的なアドレス解決はアセンブラがやってくれるため、パスを分けたり複雑な前方宣言用構文を無理に作り込まなくても安全に解決できます。


まさにその通りです！実装すべきポイントが完璧に整理されていますね。

手続きの導入によって、これまでの「一本道（フラット）」な構造から、手続きごとにスコープと実行領域が作られる「階層（ネスト）」構造へと変化するため、それらの関数群とスタック管理がキーになります。

## 🏗️ 各関数で実装すべき役割とスタック管理

### 1. `outblock()` の修正（`procedure` の追加）

大域変数（`var`）の宣言をパースした後に、手続き定義（`procedure`）が並ぶループを追加します。

* **処理の流れ**:
1. `procedure` トークンを見つけたら、手続き名（`ident`）を**大域記号表**に種類 `PROC` として登録し、その手続き固有のラベル（例: `L_proc_hanoi`）を割り当てます。
2. 引数リストの宣言（カッコ内の変数名リスト）をパースし、これらを**局所記号表**に登録します（オフセットの計算もここで行います）。
3. セミコロン `;` を挟んで、手続きの本体処理である `inblock()` を呼び出します。



### 2. `inblock()` の新規作成

手続き本体のためのブロック処理関数です。大域ブロック（`outblock`）と似ていますが、「局所変数を管理する」**点と**「プロローグ・エピローグ（スタック管理）を吐き出す」点が異なります。

* **処理の流れ＆スタック管理**:
1. 手続きの開始直後に、局所変数宣言（`var`）があればパースし、**局所記号表**に登録します。
2. **【プロローグの出力】**: 手続きの開始ラベルを出力し、フレームを構築するコードを生成します。
```text
push BR        ; 動的リンクとして呼び出し元のBRを退避
mov BR, SP     ; BRを現在のスタックトップに更新
sub SP, [局所変数の数] ; 局所変数分の領域を確保

```


3. 本体である `statement()` を呼び出して、中の処理をパース・コンパイルします。
4. **【エピローグの出力】**: 手続きから抜ける直前に、フレームを解体して戻るコードを生成します。
```text
mov SP, BR     ; スタックポインタをBRの位置に戻す（局所変数の解放）
pop BR         ; 呼び出し元のBRを復元
ret            ; 戻り番地（PC）をpopして呼び出し元へ戻る

```


5. 手続きのパースが終わったら、局所記号表をクリア（リセット）して次の手続き定義に備えます。



### 3. `statement()` の修正 ＆ `paramlist()` の作成（呼び出し側）

文の先頭が識別子（`ident`）で、それが手続き名だった場合の「手続き呼び出し」の処理です。

* **`paramlist()` の処理とスタック管理**:
1. 開きカッコ `(` を確認します。
2. カッコ内の各引数を `expression()` で評価します。評価結果はレジスタ（例: $r0$）に入るので、すぐさまスタックに積みます。
```text
push r0        ; 引数をスタックに積む（値渡し）

```


3. カンマ `,` がある限りループし、最後に閉じカッコ `)` を確認します。


* **`statement()` 側での呼び出しと後始末**:
1. 引数をすべて積み終わったら、対象手続きのラベルへジャンプします。
```text
call L_proc_hanoi ; 戻り番地が自動でスタックに積まれ、手続きへジャンプ

```


2. **【重要：引数の破棄】**: 手続きから `ret` で戻ってきた後、呼び出し側が積んだ引数の分だけスタックポインタを戻してスタックを綺麗にします。
```text
add SP, [引数の個数] ; 積んだ引数分の領域を解放

```

## ⚠️ 変数アクセス（`BR` 相対）の注意点

スタック管理において最も間違いやすいのが、`expression()` 内などで変数（`ident`）をロード・ストアするときのアドレス計算です。

* **引数へのアクセス**: `BR` より高い番地（プラス側）にあります。戻り番地や動的リンクのサイズを考慮して `[BR + 2]` や `[BR + 3]` のようになります。
* **局所変数へのアクセス**: `BR` より低い番地（マイナス側）にあります。確保した順に `[BR - 1]`、`[BR - 2]` のようになります。

まずは記号表の切り替えと、`inblock()` でプロローグ・エピローグのアセンブリ文字列（`push BR` や `ret` など）を正しく出力する骨組みから作っていきましょう！
