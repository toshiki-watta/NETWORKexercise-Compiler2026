# 作成実験3：数式拡張（ボトムアップ構文解析・演算子順位法）実装方針

演算子の優先順位（乗除 > 加減）とカッコ `()` のネストに対応するため、自作のデータ構造（スタック）を用いた**演算子順位構文解析法**を実装し、複雑な数式から中間コード（4つ組）またはアセンブリコードを正しく生成する 。

## 📋 1. 事前準備とスタックデータ構造の定義

ボトムアップ解析では、トークンを一時的に保持するためのスタックを自前で実装する必要があります 。

* [ ] **スタックの定義と領域確保**
* [ ] 演算子（`+`, `-`, `*`, `div`, `(`, `)`, `$ `）を格納する演算子スタック（op_stack）を定義する 。


* [ ] 被演算子（識別子、数値、一時変数 $Ti$ など）のアドレスや情報を格納する被演算子スタック（val_stack）を定義する 。




* [ ] **スタック操作関数（基本パーツ）の実装**
* [ ] `push_op()`, `pop_op()`, `top_op()` の実装（演算子用）。
* [ ] `push_val()`, `pop_val()`, `top_val()` の実装（被演算子用）。

## 📋 2. 演算子優先順位マトリクスの定義

隣り合う2つの演算子の優先順位を判定するための関数、または2次元配列（マトリクス）を定義します 。
直感的には、「スタックのトップにある演算子」**と**「新しく読み込んだ演算子（入力）」の優先順位を比較します 。

### 演算子の優先順位関係（付録Dの仕様に基づく設計例）

| スタックトップ \ 入力 | `+`, `-` | `*`, `div` | `(` | `)` | `$ ` |
| --- | --- | --- | --- | --- | --- |
| **`+`, `-**` | `>` (還元) | `<` (シフト) | `<` (シフト) | `>` (還元) | `>` (還元) |
| **`*`, `div**` | `>` (還元) | `>` (還元) | `<` (シフト) | `>` (還元) | `>` (還元) |
| **`(`** | `<` (シフト) | `<` (シフト) | `<` (シフト) | `=` (消去) | エラー |
| **`)`** | `>` (還元) | `>` (還元) | エラー | `>` (還元) | `>` (還元) |
| **`$ `** | `<` (シフト) | `<` (シフト) | `<` (シフト) | エラー | 終了 |

> **💡 判定ルールの言語化**
> * `スタックトップ < 入力` の場合：まだ計算できないため、入力をスタックに*シフト（追加）する 。
>  `スタックトップ > 入力` の場合：スタック側の方が優先度が高いため、スタックから演算子と被演算子を取り出してリデュース（還元・計算コード出力）**を行う 。
> 
> 

* [ ] **優先順位判定関数 `get_priority(op1, op2)` の実装**
* [ ] 2つの演算子を受け取り、`>` (還元すべき) か、`<` (シフトすべき) か、`=` (カッコのペア) かを返すロジックを実装する 。

## 📋 3. ボトムアップ構文解析ルーチン `parse_expression_bottomup()` の実装

従来の一次元的な `eval_to_r0()` を完全に置き換える、ループによる解析アルゴリズムを記述します 。

* [ ] **解析の初期化**
* [ ] 演算子スタックの底に番兵として `$ ` （数式の始まり）を積む 。




* [ ] **解析メインループ（トークン処理）**
* [ ] 現在のトークンが被演算子（IDENTIFIER または NUMBER）の場合：
* [ ] そのまま被演算子スタック（val_stack）に `push` し、次のトークンへ進む（`getsym()`） 。




* [ ] 現在のトークンが演算子（`+`, `-`, `*`, `div`, `(`, `)`, `$ `）の場合：
* [ ] `op_matrix[top_op()][current_tok]` を評価する 。


* [ ] **【シフト `<` 】** の場合：
* [ ] 現在の演算子を演算子スタックに `push` し、次のトークンへ進む（`getsym()`） 。




* [ ] **【還元 `>` 】** の場合：
* [ ] 演算子スタックから `pop_op()` して演算子（例：`*`）を取り出す 。


* [ ] 被演算子スタックから連続で2回 `pop_val()` し、右辺と左辺の要素を取り出す 。


* [ ] **コード生成を行う（4つ組中間コード、または直接アセンブリ）** 。


* [ ] 計算結果の格納先（一時変数 $Ti$ や対象レジスタ情報）を被演算子スタックに `push_val()` する 。


* [ ] *注意: トークンは進めず、同じ入力トークンでもう一度スタックトップと比較する* 。




* [ ] **【消去 `=` 】** の場合（スタックトップが `(` で、入力が `)` のとき）：
* [ ] カッコが正しく閉じたことを意味するため、演算子スタックから `(` を `pop_op()` して消去する。
* [ ] 閉じカッコを消費するために `getsym()` を呼び出し、次のトークンへ進む。


* [ ] **【終了】** の場合（スタックトップが `$ ` で、入力も `$ ` のとき）：
* [ ] ループを抜け、解析成功。最終的な計算結果は被演算子スタックのトップに残る 。

## 📋 4. コード生成部分（還元時のアセンブリ出力）の実装

ボトムアップの還元（リデュース）が発生した瞬間に、どのようなコードを吐き出すかを定義します。今回は中間コード（4つ組）を挟まずに直接アセンブリを生成する場合の方針です 。

* [ ] **レジスタ・シミュレートの破綻を防ぐ工夫**
ボトムアップでは、式が左から右へ解析されるにつれて、まだ使わない計算結果がスタックにどんどん溜まります 。


* [ ] 選択肢A：ターゲットマシンのスタック命令（`push r0` / `pop r1`）を利用して、還元時にレジスタ間で安全に演算させる 。


* [ ] 選択肢B：コンパイラ内部で仮想的な一時メモリ領域（アドレス $T0, T1, \dots$）を割り当て、還元ごとに `store` と `load` を行う安全なコードを出力する 。




* [ ] **各演算のコード生成実装**
* [ ] `+`, `-` の還元：退避されていた左辺の値と右辺の値をレジスタに揃え、`addr` や `subr` を出力 。


* [ ] `*`, `div` の還元：同様に `mulr` や `divr` を出力 。
